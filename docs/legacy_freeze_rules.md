# 旧审计平台冻结规则

## 冻结背景

旧审计平台 `E:\AI生成代码\pytools_new\apps\svn_check` 仍在持续新增规则和辅助能力，新审计平台 `E:\AI生成代码\代码审查平台` 已经形成 React + REST API + 任务模型 + 报告 JSON 的新架构。两边已经出现规则文件、服务层、配置模型和展示方式分叉。

本规则用于避免继续扩大双线差异。旧平台后续只作为存量规则验证和资产来源，不再作为新功能主战场。

## 旧平台定位

旧平台定位为：

- 存量规则资产库。
- P0/P1 阻断性问题的临时修复点。
- 规则实验验证环境。
- 只读盘点、差异分析和迁移说明来源。

旧平台不再承担新页面、新交互、新 API、新部署能力的建设。

## 新平台定位

新平台定位为：

- 后续业务功能的唯一主线。
- React 页面承载层。
- REST API 与任务模型承载层。
- 报告 JSON schema 承载层。
- 权限、日志、配置管理、部署能力承载层。
- 从旧平台逐步迁移规则和服务能力的目标平台。

## 旧平台允许修改范围

旧平台只允许以下修改：

- 修复 P0/P1 阻断性 bug。
- 做规则实验验证。
- 做只读盘点和差异分析。
- 补充迁移说明。
- 为迁移准备最小测试样例或说明文档。

所有允许修改都必须登记到功能同步登记表。

## 旧平台禁止修改范围

旧平台禁止以下修改：

- 新增 Streamlit 页面。
- 新增复杂交互。
- 新增未登记的业务功能。
- 继续扩大配置依赖。
- 直接复制旧平台文件到新平台并覆盖同名文件。
- 在未做函数级比对的情况下同步同名文件。
- 把新平台已有的任务模型、API、报告 JSON 逻辑回写到旧平台。
- 把真实账号、密码、token、内网连接串写入文档、日志或代码注释。

## 只能在新平台开发的功能

以下功能只能在新平台开发：

- React 页面。
- REST API。
- 任务模型。
- 报告 JSON schema。
- 权限控制。
- 用户操作日志和审计日志。
- 配置管理。
- 可部署能力。
- 前后端联调能力。
- 需要长期维护的公共组件。
- 需要面向用户交互的筛选、分页、弹窗、抽屉、返回路径。

## 可以先在旧平台验证的规则

以下内容可以先在旧平台验证，但必须登记：

- 纯规则函数实验。
- SQL / Python / 调度规则的边界样例。
- 元数据查询口径验证。
- 词根、资产表、结果表登记等数据口径验证。
- SVN 差异识别规则验证。

验证完成后，必须明确迁移目标：

- 新平台目标文件。
- 目标 API 或任务字段。
- 报告 JSON 字段。
- 前端展示位置。
- 测试用例。

## 旧平台变更登记信息

旧平台每次变更必须登记：

- 功能模块。
- 功能说明。
- 旧平台入口。
- 新平台目标入口。
- 涉及规则文件。
- 涉及服务文件。
- 涉及配置。
- 涉及数据表。
- 报告 JSON 字段。
- 前端页面。
- 测试用例。
- 迁移状态。
- 优先级。
- 风险。
- 备注。

## 敏感配置处理要求

- 不输出数据库账号、密码、token、真实连接串、内网 IP 原文。
- 发现敏感配置时，只记录文件路径和风险类型。
- 真实配置不得复制到迁移文档。
- 示例配置必须使用占位符。
- 日志文件不作为迁移材料直接提交。
- 涉及 `database.yaml`、`audit_datasource.yaml`、`svn.yaml`、集群配置时，先做脱敏审查。

## Codex 后续执行规则

Codex 后续处理该项目时必须遵守：

- 默认不修改旧平台业务代码。
- 默认不提交 git。
- 默认不做自动同步。
- 修改旧平台前必须确认是否属于允许范围。
- 修改新平台业务代码前必须先确认对应登记项和迁移 round。
- 同名文件不得直接覆盖，必须先做函数级差异快照。
- 输出报告时只引用关键路径和简要说明，不贴大段源码。
- 发现敏感配置只标记风险，不输出具体值。
- 业务迁移优先走新平台 API、任务模型和报告 JSON。
