# Public Release History Cleanup Plan

本方案用于 P0-S2 公开发布前历史扫描与脱敏执行方案评审。本轮只形成方案和清单，不执行真实清理，不删除文件，不重写 Git 历史，不运行 `git filter-repo`、BFG、`git reset` 或递归删除命令。

## 本轮只读扫描结论

本轮扫描仅记录文件路径、风险类型和建议动作；不记录真实账号、密码、token、IP、连接串、内网域名、业务系统名、真实表名或真实 SQL 内容。涉及示例值时统一使用 `<REDACTED>` 或 demo placeholder。

## Git 历史处理策略

### 方案 A：现仓库直接清理后公开

优点：

- 操作成本最低，不需要迁移仓库或重建远端。
- 保留完整提交记录、issue/PR 关联和现有协作上下文。
- 适合历史已经被证明干净，仅当前工作区存在少量可模板化配置的情况。

缺点：

- 工作区清理不能清除历史提交中的敏感值。
- 已推送到远端或被 fork 的敏感提交无法通过普通删除消除传播风险。
- 容易误判“当前文件已脱敏”等于“仓库可公开”。

风险：

- 如果历史中曾出现真实连接串、账号、token、SVN 凭据、内网地址或真实业务数据，公开当前仓库会暴露历史内容。
- 图片、SQL、mock 数据和文档中的真实信息可能不被普通关键字扫描覆盖。

适用条件：

- 完整 Git 历史经专业工具和人工复核确认无敏感值。
- 当前工作区仅存在本地配置、缓存或 demo 可替换内容。
- 所有配置均已模板化，截图和静态素材已脱敏。

不适用条件：

- 历史中出现过真实连接串、账号、内网地址、私有 SQL、真实业务数据或私有二进制文件。
- 不能完整确认所有分支、tag、stash、子模块或旧远端镜像的历史状态。
- 已有外部协作者或远端 fork，无法保证同步清理。

### 方案 B：重写历史后公开

需要工具：

- `git filter-repo`
- BFG Repo-Cleaner
- `gitleaks`、`trufflehog`、`detect-secrets`、`git-secrets` 用于清理前后扫描

操作风险：

- 重写历史会改变 commit hash，影响分支、tag、PR、CI、部署记录和协作者本地仓库。
- 规则不完整会漏删敏感值；规则过宽会误删正常代码或文档。
- 二进制文件、图片、压缩包、数据库文件需要额外策略，不能只依赖文本替换。

对远端和协作者的影响：

- 所有协作者必须重新同步或重新 clone。
- 已存在的 fork、clone、备份、CI 缓存和包产物不会自动消失。
- 远端需要强推或重建，受保护分支和 tag 需要单独处理。

何时才值得做：

- 必须保留现有仓库身份、issue/PR 历史或内部审计链路。
- 敏感内容范围明确、可用规则精确定位，且协作者可统一切换。
- 清理后仍会保留为内部仓库，公开前再做二次验证。

回滚难度：

- 高。必须提前创建离线备份和远端镜像备份。
- 回滚可能需要恢复旧远端或重新推送备份引用。
- 如果清理后的仓库已经公开，回滚不会撤回已暴露内容。

### 方案 C：新建干净公开仓库

做法：

- 从当前仓库导出脱敏后的公开版文件。
- 不带历史，或只导入经过复核的干净历史。
- 只包含公开所需代码、模板配置、demo 数据、公开文档和可重建脚本。

优点：

- 最大限度隔离历史敏感值风险。
- 不影响内部仓库、旧平台仓库、现有分支和协作记录。
- 公开版边界清晰，可在导出目录内做独立扫描、测试和人工复核。
- 对截图、SQL、mock 数据、配置模板和文档可按公开标准重建。

缺点：

- 失去完整内部提交历史。
- 需要维护内部仓库与公开仓库的同步流程。
- 首次导出和后续同步需要明确白名单和复核机制。

推荐程度：

- 推荐。只要历史中出现过真实连接串、账号、内网地址、SVN 凭据、私有 SQL 或真实业务映射，优先选择新建干净公开仓库。
- 当前项目已经在历史和旧平台路径中出现配置类风险信号，公开发布策略应以方案 C 为默认建议。

## 明确建议

- 如果历史中出现过真实连接串、账号、token、SVN 凭据、内网地址、真实业务系统名、真实表名或私有 SQL，优先推荐方案 C：新建干净公开仓库。
- 如果只是在当前工作区存在敏感配置，且完整历史扫描确认无风险，才考虑方案 A。
- 方案 B 仅在必须保留当前仓库身份且能承受协作影响时使用；它不是公开发布的默认首选。
- 在没有完整历史扫描前，不建议直接开源当前仓库。
- 本轮扫描已发现敏感配置类路径进入历史的风险信号，因此建议公开发布默认采用方案 C，并将真实清理执行另开独立 round。

## 执行前备份

- 要做什么：冻结内部仓库当前状态，导出只读备份，记录当前分支、tag、远端和 commit hash。
- 涉及文件类型：Git refs、文档、配置、源代码、静态素材、数据库或日志产物。
- 风险：没有备份时，误删或误清理后难以恢复；备份本身也可能包含敏感值。
- 验证方式：校验备份可 clone 或可解包；记录备份位置但不公开。
- 回滚方式：从离线备份恢复内部仓库；公开仓库不使用含敏感历史的备份直接发布。

## 工作区扫描

- 要做什么：扫描当前工作区的敏感关键字、配置文件、数据库文件、日志、缓存、截图和静态原型素材。
- 涉及文件类型：`.env`、`.local`、`.db`、`.sqlite`、`.log`、YAML、JSON、SQL、Markdown、PNG/JPG、mock 数据。
- 风险：普通文本扫描无法覆盖图片、压缩包、数据库二进制和编码异常文件。
- 验证方式：输出仅保留路径和风险类型；人工打开高风险文件复核但不复制真实值到文档。
- 回滚方式：本步骤只读，无需回滚。

## Git 历史扫描

- 要做什么：扫描所有分支、tag 和历史提交中的敏感关键字、配置文件路径、数据库文件路径和静态素材路径。
- 涉及文件类型：历史中的配置、SQL、SQLite、日志、截图、mock 数据、文档。
- 风险：历史扫描可能输出真实值；命令输出不得粘贴到公开文档。
- 验证方式：使用 `git log --all --name-only`、`git grep` 和专业工具交叉验证；人工复核只记录路径、风险类型、建议动作。
- 回滚方式：本步骤只读，无需回滚；若后续执行历史重写，必须依赖执行前备份回滚。

## 文件分类

- 要做什么：把文件分为删除、模板化、替换为 demo、保留但复核、不进入公开版。
- 涉及文件类型：运行库、日志、缓存、配置、mock、SQL、截图、文档、内部审计材料。
- 风险：分类过宽会丢失公开版必要功能；分类过窄会遗漏敏感值。
- 验证方式：形成公开版文件白名单和排除清单，双人复核。
- 回滚方式：从内部仓库重新导出或恢复白名单版本。

## 配置模板化

- 要做什么：将 `database.yaml`、`audit_datasource.yaml`、`svn.yaml`、`.env.local` 和工具配置改为 `.example` 或环境变量说明。
- 涉及文件类型：YAML、ENV、JSON、README 配置片段。
- 风险：模板中保留真实 host、账号、路径或内部系统名。
- 验证方式：扫描模板内容，确认只包含 `<REDACTED>`、`demo_*`、`localhost` 或环境变量名。
- 回滚方式：内部仓库保留真实私有配置；公开仓库只回滚模板文件。

## mock/demo 数据替换

- 要做什么：替换 mock 数据、示例表名、示例作业名、示例系统名和示例报表数据。
- 涉及文件类型：JS/JSON mock、SQL demo、测试夹具、README 示例。
- 风险：真实业务语义通过命名、字段组合或截图间接泄露。
- 验证方式：使用 synthetic 命名空间，例如 `demo_system`、`demo_job`、`demo_table`；人工复核业务语义。
- 回滚方式：保留内部测试数据在私有仓库；公开版重新生成 demo 数据。

## 文档脱敏

- 要做什么：复核 README、docs、架构说明、迁移报告、回归命令和安全清单。
- 涉及文件类型：Markdown、TXT、HTML、导出的报告。
- 风险：迁移记录中可能出现真实路径、真实业务系统、真实表名、真实错误信息。
- 验证方式：关键字扫描加人工复核；文档只写路径、风险类型和占位符。
- 回滚方式：内部文档保留在私有仓库；公开文档从脱敏版本恢复。

## 截图和静态素材复核

- 要做什么：复核 `静态原型代码/screenshots/*` 和其他图片素材。
- 涉及文件类型：PNG、JPG、GIF、SVG、HTML 原型。
- 风险：截图中可能含真实平台 URL、账号、业务对象、组织名称、时间戳或内部菜单。
- 验证方式：人工逐张查看；优先使用 demo 环境重截，不建议只做局部打码。
- 回滚方式：公开仓库删除或替换为 demo 截图；内部素材留在私有仓库。

## 回归测试

- 要做什么：在脱敏公开版上执行后端单测、自检和前端构建，确认模板化后仍可运行。
- 涉及文件类型：tests、backend、frontend、配置模板、mock 数据。
- 风险：脱敏后默认配置不可用、mock 数据缺字段、前端构建失败。
- 验证方式：执行 `D:\miniconda3\python.exe -m unittest discover -s tests`、`D:\miniconda3\python.exe backend\dev_selfcheck.py`、`cd frontend && npm run build`。
- 回滚方式：从公开版导出基线恢复；修复 demo 配置或 mock 数据后重新测试。

## 人工复核

- 要做什么：由至少一名未参与脱敏的人进行二次复核。
- 涉及文件类型：全部公开候选文件、历史扫描摘要、发布说明。
- 风险：自动扫描误报和漏报并存，尤其是中文业务名、图片和 SQL。
- 验证方式：复核人只在清单中确认路径和风险类型，不记录真实值。
- 回滚方式：复核失败则停止发布，回到文件分类或模板化步骤。

## 最终发布方式选择

- 要做什么：在方案 A、B、C 中选择最终发布方式。
- 涉及文件类型：完整仓库、导出公开版、历史引用、发布说明。
- 风险：在历史未完全确认前直接公开当前仓库。
- 验证方式：发布前 gate 必须包含工作区扫描、历史扫描、专业工具扫描、人工复核、测试通过和无真实值确认。
- 回滚方式：公开前删除候选远端或废弃候选仓库；公开后发现泄露需立即撤回、轮换凭据并发布安全处理记录。

## 建议扫描命令

以下命令仅作为未来执行建议。本轮不执行清理命令，不安装工具，不联网，不重写历史。

```powershell
git status --short
git ls-files

git grep -n -I "password"
git grep -n -I "token"
git grep -n -I "jdbc"
git grep -n -I "dsn"
git grep -n -I "secret"
git grep -n -I "svn"

```

建议只输出路径的工作区扫描：

```powershell
rg -l -i "password|passwd|token|secret|jdbc|dsn|database|datasource|svn|sqlite|credential" .
rg --files | rg -i "(^|/)(\.env|.*\.local|.*\.db|.*\.sqlite|.*\.sqlite3|.*\.log)$|(^|/)(logs?|cache|tmp|temp|dist|build)(/|$)"
```

建议只输出路径的历史扫描：

```powershell
git log --all --name-only --pretty=format:
git rev-list --all | ForEach-Object { git grep -l -I -i -E "password|passwd|token|secret|jdbc|dsn|database|datasource|svn|sqlite|credential" $_ 2>$null } | Sort-Object -Unique
```

建议专业工具：

- `gitleaks`
- `trufflehog`
- `detect-secrets`
- `git-secrets`

使用专业工具时，报告不得直接进入公开仓库；如报告包含真实值，只保存在私有审计位置，并在公开文档中改写为路径、风险类型和建议动作。

## 文件处理策略

### 删除

- SQLite 运行库：`**/*.db`、`**/*.sqlite`、`**/*.sqlite3`。
- 日志：`**/*.log`、`**/logs/**`。
- 缓存：`**/cache/**`、`**/__pycache__/**`、前后端构建缓存。
- 临时文件：`tmp`、`temp`、本地导出、中间产物。
- 私有初始化 SQL：包含真实库表、真实字段语义或真实业务映射的 SQL。

### 模板化

- `database.yaml`
- `audit_datasource.yaml`
- `svn.yaml`
- `.env.local`
- 工具配置和本地路径配置

模板中只允许字段结构、环境变量名、`<REDACTED>`、`demo_*` 或 `localhost` 级别占位。

### 替换为 demo

- mock 数据
- 示例表名
- 示例作业名
- 示例系统名
- 截图素材
- 示例报告和示例 SQL

所有 demo 数据应为 synthetic，不从真实业务数据改写。

### 保留但复核

- `README.md`
- `docs/*`
- 架构说明
- 迁移报告
- 回归命令
- 代码中公开必要的配置加载逻辑

保留条件是无真实账号、密码、token、真实内网 IP、真实连接串、内网域名、真实业务系统名和真实业务数据。

### 不进入公开版

- 内部审计材料
- 真实业务数据
- 内网部署说明
- 真实平台截图
- 真实客户或组织信息
- 旧平台真实配置
- 真实迁移中间产物

## P0-S2 结论

- 本轮不执行真实清理，不删除文件，不重写历史。
- 当前风险判断支持“公开前必须先做完整历史扫描和人工复核”。
