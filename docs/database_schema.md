# 数据库表结构

本文档说明当前代码审计平台使用的运行表和审计元数据表，面向开发、部署与数据库运维人员。

> 本文档只便于查阅，不是建表事实来源。实际结构以
> `backend/app/db/sql/*/schema.sql`、
> `backend/app/modules/metadata/init/postgres_schema.sql` 和
> `backend/migrations/manifest.json` 为准。

## 结构边界

- **运行表（runtime）**：保存项目、审计任务、报告、问题明细和 FineReport 分析项。
- **元数据表（metadata）**：保存审计规则只读查询所需的作业、程序、计划、词根等兼容数据。
- 两类表可以部署在同一个数据库和 schema 中，但职责不同，不能把 metadata 初始化 SQL 合并到 runtime schema。
- 生产运行支持 PostgreSQL 和 DWS；SQLite 结构仅用于测试与数据迁移兼容。

## Runtime 表

默认 PostgreSQL/DWS schema 为 `dwp`，默认表前缀为 `p_audit_`。运行时查询可由数据库 profile 的 `schema`、`table_prefix` 和 `table_name_stems` 调整；代码中使用逻辑表名，通过 `backend/app/db/tables.py` 解析物理表名。当前 PostgreSQL/DWS 基线 SQL 声明的是下表默认名称，使用自定义命名时必须另行准备匹配的迁移。

| 逻辑表 | 默认物理表 | 用途 |
| --- | --- | --- |
| `projects` | `dwp.p_audit_project_config` | 审计项目配置 |
| `audit_tasks` | `dwp.p_audit_run` | 任务来源、状态、进度和执行信息 |
| `task_reports` | `dwp.p_audit_run_report` | 每个任务的完整 JSON 报告 |
| `audit_results` | `dwp.p_audit_run_issue` | 规则问题明细 |
| `fine_report_items` | `dwp.fine_report_items` | FineReport 文件和数据集分析结果 |

## Metadata 表

metadata 初始化 SQL 当前仅提供 PostgreSQL 版本，默认位于 `dwp` schema。这些表保留旧系统兼容列名，业务含义由 metadata service 的字段映射解释；不要仅凭通用列名重命名字段。

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `dwp.p_job_hjj` | `a`–`w` TEXT、`x` INTEGER、`y`–`z` TEXT、`aa`–`ab` TEXT | 作业与依赖信息 |
| `dwp.p_program_hjj` | `a`–`k` TEXT | 加工程序与结果表信息 |
| `dwp.p_plan_hjj` | `a`–`f` TEXT | 调度计划信息 |
| `dwp.p_role_hjj` | `a` TEXT | 角色目录 |
| `dwp.p_fine_hjj` | `a` TEXT | FineReport 目录 |
| `dwp.p_job_outfile` | `a`、`b` TEXT | 作业输出路径映射 |
| `dwp.p_para_table_lists` | `para_table_name` TEXT | 参数表清单 |
| `dwp.p_recv_dwf` | `table_name`、`recv_plan` TEXT | 接收结果表与计划映射 |
| `dwp.p_term_root` | `root_code` TEXT | 词根目录 |

当前 metadata SQL 没有为这些兼容表声明主键、外键或索引。`p_job_hjj.x` 初始化时会把既有非整数列转换为 INTEGER；生产升级前应先确认旧数据可转换。

## 方言差异

| 项目 | PostgreSQL | DWS | SQLite |
| --- | --- | --- | --- |
| 自增主键 | `GENERATED BY DEFAULT AS IDENTITY` | `BIGSERIAL` | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| 时间字段 | `TIMESTAMP` | `TIMESTAMP` | `TEXT` |
| runtime 外键 | 报告、问题表声明外键 | 当前 schema 未声明外键 | 报告、问题表声明外键 |
| schema | 默认 `dwp` | 默认 `dwp` | 无 schema |
| 使用范围 | 生产 | 生产 | 测试/迁移兼容 |

## 初始化与迁移

版本化迁移由 `backend/migrations/manifest.json` 登记，当前版本为：

| 版本 | 内容 |
| --- | --- |
| `0001` | runtime 基线结构 |
| `0002` | 为任务增加 `idempotency_key` |
| `0003` | 移除问题明细的 `line_no` |
| `0004` | 为问题明细的 `task_id` 增加索引 |

在 `backend` 目录执行：

```powershell
python scripts/schema_migrate.py status
python scripts/schema_migrate.py apply
python scripts/init_pg.py
```

- `schema_migrate.py` 使用 `schema_migrations` 表记录版本、名称、校验和、执行时间和耗时。
- 应用启动不会隐式执行版本化迁移。
- `init_pg.py` 初始化 metadata 表；不要把它当成 runtime 迁移命令。
- 已发布迁移文件受校验和保护，不应直接修改；结构变化应新增递增版本。

更多操作步骤见 [数据库迁移](db_migration.md) 和 [配置说明](configuration.md)。
